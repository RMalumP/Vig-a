GitHub Actions

Conectado como al repositorio . GitHub comprobará las páginas marcadas con la etiqueta «GitHub» aunque tengas el ordenador apagado, y te avisará por Telegram o ntfy.

    Cómo prepararlo (una sola vez)
    1. Sube al repositorio .github/workflows/vigia.yml y vigia/vigia-action.mjs.
    2. En el repositorio, ve a Settings → Secrets and variables → Actions → Secrets y crea TELEGRAM_TOKEN y TELEGRAM_CHAT_ID, o bien NTFY_TOPIC (y opcionalmente NTFY_SERVER).
    3. En cada página que quieras vigilar desde GitHub, abre «Ajustes» y marca «Vigilar también desde GitHub Actions».
    4. Pulsa «Enviar lista a GitHub». Se guarda como variable privada del repositorio y se activa el workflow.
    5. Pulsa «Ejecutar ahora» para probarlo. Después se ejecutará solo cada 15 minutos.

    La lista se guarda en variables del repositorio, que solo ven quienes tienen acceso de escritura. Las copias (forks) no reciben ni variables ni secretos, así que el workflow no se ejecuta en ellas.

      Copia de seguridad y conexión

      Exportar e importar

      Sirve para pasar tus páginas a otro navegador u ordenador. Al importar, las páginas que ya tienes no se duplican.

      Proxy propio

      Opcional. Con un proxy propio (por ejemplo, un Cloudflare Worker gratuito con el archivo cloudflare-worker.js) no dependes de los proxies públicos. En modo automático se prueba primero.

      Si algo no funciona

      Muchas webs no dejan que otra página lea su contenido (bloqueo CORS). En modo automático, Vigía prueba tu proxy propio, el acceso directo y varios proxies públicos. Si ninguno responde, esa web no se puede vigilar desde el navegador, pero sí desde GitHub Actions.

      Chromium ralentiza las pestañas en segundo plano, a veces hasta una comprobación por minuto. Para intervalos cortos, usa la ventana flotante o deja esta pestaña en una ventana aparte.

      Las notificaciones del sistema funcionan en GitHub Pages (https) y en localhost; abriendo el archivo directamente (file://) puede que Chromium no las permita.
